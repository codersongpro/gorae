# 나눔 곳간 운영 설정 (구글 폼 '고래곳간 자료공유' → 구글 시트 → 구글 드라이브)

서버 없이 구글 폼·시트·드라이브로 운영합니다. 나눔 곳간 작품은 모두 **검수 전**이며 인증 곳간과 구분해 표시합니다.

```
[공유] 작품 카드 → [자세히] → 나눔 곳간에 공유하기
  ① 업로드할 파일 저장(.html, 맨 앞 주석에 분류·레시피 정보)
  ② 미리 채워진 구글 폼 열기 (닉네임·제목·앱 종류·설명·자료 종류·웹 앱 주소 자동)
  ③ 폼 제출 → 비공개 원응답 → 운영자 확인 → 공개목록
[받기] 나눔 곳간 탭 → 공개목록 CSV 불러오기 → 검색·앱 종류 거르기 → [가져오기]
  → 드라이브 파일 받기 → 검증 → 내 곳간(출처: 나눔 곳간) → 실행 전 출처 확인
```

## 0. 분류 정보는 어떻게 넘어가나 (폼 문항을 늘리지 않음)
폼의 '앱 종류'(교무행정·수업자료·학생관리·기타)는 예전 분류라 실제 분류를 담지 못합니다. 그래서 고래곳간은 **4번 설명 칸 끝**에 아래 글을 자동으로 붙여 미리 채웁니다. 시트에서 읽을 때 이 글을 원래 작품 필드로 되살립니다(`shared/market.js`의 `buildClassificationText` / `parseClassificationText`).
웹앱은 HTML 파일 안에 작품 정보를 숨길 수 없으므로 이 글이 유일한 통로입니다. HTML 파일은 맨 앞 주석의 작품 정보가 우선하고, 빈 칸만 이 글로 채웁니다.

```
피자 조각으로 분수 크기를 비교해요.

[고래곳간 분류 정보]
수업 › 교과 학습 › 게임·퀴즈
[lesson/subject_activity/game]
형태: webapp
학교급: elementary
학년: 4
교과: 수학
영역: 수와 연산
단원: 분수
주제: 분수의 크기 비교
성취기준: [4수01-12]
시간: 10
활동형태: individual
대상: student
태그: 분수, 게임, 형성평가
```

- 보존되는 값: domain · category · subcategory · contentType · artifactType · learningMode · selfDirected · difficulty · creationMethod · schoolLevel · grade · subject · area · unit · lessonNo · topic · standard · estimatedMinutes · groupType · audience · tags
- 알 수 없는 값(목록에 없는 카테고리·학교급 등)은 버립니다. 시트는 누구나 고칠 수 있다고 봅니다.
- `공개목록` 탭으로 옮길 때 **설명 칸을 통째로** 옮겨야 분류가 유지됩니다. 폼에 '분류' 문항을 따로 만들면 `MARKET.entry.category`에 entry 번호를 넣어 같은 글을 그 칸에도 채울 수 있습니다(시트 열 이름에 '분류'가 들어가면 그 열도 읽음).

## 1. 폼 문항 (지금 구성 그대로 사용)
| 섹션 | 문항 | 고래곳간이 채우는 값 |
| --- | --- | --- |
| 1 | 1. 제작하신 분의 닉네임 | 저장해 둔 닉네임 |
| 1 | 2. 제작한 앱의 제목 | 작품 제목 |
| 1 | 3. 제작한 앱의 종류 (교무행정·수업자료·학생관리·기타, 복수) | 수업 → 수업자료 / 학급운영·학생생활 → 학생관리 / 나머지 업무 → 교무행정 |
| 1 | 4. 도구에 대한 설명 | 작품 설명 + 끝에 '분류 정보' 글 (0절) |
| 1 | 5. 만드신 자료의 종류 → HTML·exe: 섹션 3 / 배포한 웹 앱: 섹션 2 | 작품 형태 |
| 2 | 배포하신 웹 앱 주소 | 주소 + 작품 정보 한 줄 |
| 3 | 교육 자료를 업로드 (기존 폼 문항명은 운영자가 변경) | (사용자가 ①에서 저장한 파일을 올림) |

### 꼭 고칠 것
- **섹션 2 다음 → "양식 제출"** 로 바꾸세요. 지금은 "다음 섹션으로 진행하기"라 웹 앱을 낸 사람도 섹션 3 파일 업로드(필수)에서 막힙니다. (미리보기에서 섹션 2 버튼이 '제출'이 아니라 '다음'으로 보이는 것이 그 때문입니다)
- 섹션 3 파일 문항: **"특정 파일 형식만 허용" 끄기** (HTML을 받기 위해). 최대 크기는 10MB면 충분합니다.
- 5번 선택지 글자를 바꾸면 `shared/market.js`의 `FORMAT_OPTIONS`도 같이 바꿔야 미리 채우기가 됩니다. 3번 선택지도 `KIND_OPTIONS`와 같아야 합니다.

### 실행 파일(exe)에 대해
고래곳간 규칙은 "실행 파일은 보관하지 않고 링크·SHA-256만"입니다. 앱은 EXE 작품을 **배포한 웹 앱(섹션 2)** 쪽으로 안내해 다운로드 링크·소스·SHA-256·검사 결과·실행 환경을 주소 칸에 넣습니다.
5번 선택지를 "HTML 파일"로 바꾸는 것을 권합니다.

## 2. 개인정보 — 공개 방법 (중요)
폼 설명에 나오듯 **파일을 올리면 올린 사람의 구글 이름·이메일·사진이 기록**되고, 드라이브 파일의 **소유자로 이름이 보입니다.**
응답 시트나 업로드 폴더를 통째로 공개하면 교사·학생의 실명과 이메일이 드러납니다. 그래서 아래처럼 **공개용 탭만** 게시하세요.

1. 폼 **응답** 탭 → 스프레드시트 연결. 이 응답 시트는 **비공개 그대로** 둡니다.
2. 나눔 곳간의 스프레드시트 파일 주소와 ID는 고정입니다. 새 파일로 바꾸지 않고, 같은 파일 안에 탭을 하나 더 만들어 이름을 `공개목록`으로 합니다. 1행 열 이름은 아래처럼 씁니다(고래곳간은 이 낱말로 열을 찾습니다).
   `타임스탬프 | 닉네임 | 제목 | 앱의 종류 | 설명 | 자료의 종류 | 웹 앱 주소 | 업로드`
3. 검토한 작품만 한 줄씩 옮깁니다(승인 절차가 됩니다).
   - HTML 파일은 드라이브에서 **사본 만들기** → 운영자의 `고래곳간 공개` 폴더로 옮기고, 그 **사본 링크**를 `업로드` 칸에 넣습니다. 사본은 소유자가 운영자라 올린 사람 정보가 드러나지 않습니다.
   - `고래곳간 공개` 폴더는 **링크가 있는 모든 사용자 – 뷰어**로 공유합니다.
4. **파일 → 공유 → 웹에 게시 → `공개목록` 탭 · 쉼표로 구분된 값(.csv)** → 게시 → 나온 주소를 알려 주세요(`publishedCsvUrl`).
5. 내리고 싶은 작품은 `공개목록`에서 그 줄을 지우면 다음 새로고침부터 사라집니다.

> 원응답 시트와 업로드 폴더 전체는 공개하지 않습니다. 운영 코드에서는 원응답 시트로 돌아가는 경로를 금지하며, 예전 응답 캐시도 재사용하지 않습니다. 공개목록 CSV가 아직 설정되지 않아 기본 자료만 표시됩니다.

## 3. 미리 채우기 entry 번호
폼 오른쪽 위 ⋮ → **미리 채워진 링크 받기** → 1~5번과 섹션 2 주소 칸에 아무 값이나 넣고(3번은 두 개 체크) **링크 받기** → 복사한 링크를 그대로 알려 주세요.

## 4. 고래곳간 설정 (`extension/core/market-config.js`)
| 설정 | 값 |
| --- | --- |
| `sheetId` | 고정된 나눔 곳간 파일 ID. 운영에서 원응답 요청에 사용하지 않음 |
| `publishedCsvUrl` | 같은 고정 파일에서 2-4로 게시한 `공개목록` 탭 CSV 주소 |
| `formUrl` | 폼 **게시** 후 응답자 링크 (`https://docs.google.com/forms/d/e/.../viewform`) |
| `entry.nickname` ~ `entry.address` | 3번 링크에서 확인한 `entry.숫자` |

## 5. 검수(인증 곳간)
좋은 작품은 파수꾼고래가 사본 파일을 내려받아 검수 도구(`review.html`) **2. 검수대**에서 서명 → `catalog.json` → 인증 곳간에 올립니다.

## 6. 보안
- 시트·드라이브는 https로, 쿠키 없이, 15초·2MB 상한으로만 읽고, 리다이렉트 뒤 주소가 구글이 아니면 멈춥니다. 로그인 화면으로 넘어가면 "공개되어 있지 않아요"로 안내합니다.
- 목록 단계: 제목이 있고 파일은 구글 드라이브 https 주소, 웹앱은 https 주소인 줄만 보입니다. (파일 내용은 목록 단계에서 받지 않습니다)
- 미리 보기·가져오기 단계: 형식 검사(1MB, https 등)를 통과해야 열리고, 자동 점검 결과를 보여 줍니다. 학생고래는 점검에 걸린 작품을 열 수 없고(교사 확인 필요) 담기는 교사고래만 합니다. 파일 속에 검수 서명이 있어도 떼어 내므로 나눔 곳간 작품은 인증 작품처럼 보이지 않습니다.
- 실행은 격리된 창에서 하고 외부 요청(fetch 등)은 막힙니다. 처음 실행할 때 출처 확인창이 뜹니다.

## 7. 물뿜기 (좋아요) · 고래 노래 — 설문 '고래곳간 물뿜기'
- 설문: 로그인 없이 응답, 장문형 1문항 `entry.102027181` (`extension/core/config.js`의 `feedbackFormUrl`·`feedbackEntry`)
- 응답 시트: `spoutSheetId` (링크가 있는 모든 사용자 – 뷰어). 개인정보 없이 작품 번호와 교사/학생 구분만 쌓입니다.
- 카드의 💨을 누르면 확장앱이 이 설문에 **자동 제출**하고, 모든 앱이 응답 시트를 읽어 숫자를 셉니다. 다시 누르면 **취소 보고**가 제출되어 1이 빠집니다. 같은 보고 번호는 한 번만 셉니다.
- 인터넷이 끊겨 못 보낸 물뿜기는 기기에 남았다가 다음에 앱을 열 때 다시 보냅니다.
- 시트 정리: 잘못 들어온 줄은 시트에서 지우면 다음 새로고침부터 빠집니다.
- 고래 노래(교사고래)는 [고래 노래 보내기]를 누르면 글이 미리 채워진 이 설문이 열리고 [제출]만 누르면 됩니다. 파수꾼고래가 검수대에서 작품에 붙여 다시 서명합니다.
